# 内置演示数据说明

本目录存放时档匠的合成演示数据、清单与生成规则。所有数据均由固定随机种子生成，不包含任何真实设备、组织、地址或个人信息。

## 一、文件清单

| 文件 | 数据源标识 | 采样间隔 | 名义行数 | 实际行数 | 缺失比例 | 时间范围 |
| --- | --- | --- | ---: | ---: | ---: | --- |
| sensor_high_freq.parquet | high-freq-edge | 10 秒 | 120960 | 114912 | 5% | 2025-12-18 至 2025-12-31 |
| sensor_mid_freq.parquet | mid-freq-server | 1 分钟 | 132480 | 125856 | 5% | 2025-10-01 至 2025-12-31 |
| sensor_low_freq.parquet | low-freq-iot | 1 小时 | 9504 | 9029 | 5% | 2024-12-01 至 2025-12-31 |

三组数据合计覆盖 2024-12-01T00:00:00Z 至 2025-12-31T23:59:50Z，跨度 13 个月。高频、中频和低频数据分别模拟边缘网关、本地服务器监控和离线 IoT 节点。

## 二、字段定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| timestamp | UTC 时间 | 观测时间，Parquet 中以时间戳类型保存 |
| sensor_id | 字符串 | 设备标识，均为合成标识 |
| metric_group | 字符串 | 指标分组，用于演示多标签索引 |
| temperature | 浮点数 | 环境温度，正常范围约 -40～125 |
| humidity | 浮点数 | 相对湿度，正常范围 0～100 |
| pressure | 浮点数 | 大气压，正常范围 800～1200 |

`demo_manifest.json` 记录版本、总种子、时区、描述、总时间跨度，以及每个文件的源标识、起止时间、频率、种子、名义行数、实际行数、SHA256、实际跨度和移除行数。清单是生成脚本、演示命令和校验和的共同事实来源。

## 三、生成规则

生成脚本为 `tools/generate_fixtures.py`，总体规则如下：

1. 使用固定总种子 `202501`，每个文件再使用独立种子，保证跨平台和跨次生成可复现。
2. 按名义频率生成完整时间网格，再以固定随机流移除约 5% 的采样行，模拟采集缺口。
3. 在保留行中，以确定性随机流挑选约 2% 的行，把某个指标替换为明显越界值，模拟异常读数。
4. 温度、湿度和压力按平滑趋势、周期波动与小幅噪声合成，不使用真实设备数据。
5. 写出 Parquet 后重新读取行数、时间跨度和 SHA256，并更新清单。
6. 不修改、不覆盖项目之外的任何文件。

重新生成命令：

```bash
python tools/generate_fixtures.py
```

该脚本只写入当前目录下的 `mock_sensor/` 和清单文件，不发起网络请求。重新生成可能因 pandas 或 pyarrow 版本差异导致 Parquet 字节哈希变化，因此正式发布前应复核 `demo_manifest.json` 与 `SHA256SUMS.txt`。

## 四、异常与缺失分布

缺失是随机离散点缺失，不构造整段断流。异常通过策略阈值识别：温度超出 -50～150、湿度超出 0～100、压力超出 800～1200 的观测会在读取阶段被标记，不参与指标聚合，但保留在原始文件中并计入异常数。

由于随机抽样，实际异常数量会因种子和文件长度不同而略有差异：

- 高频文件约 2298 行异常。
- 中频文件约 2517 行异常。
- 低频文件约 181 行异常。

异常行数与缺失行数均在演示任务的质量报告中可见。质量报告不修改原始 Parquet 文件。

## 五、只读约定

所有演示数据均视为只读输入。归档、索引、恢复和回滚流程只读取这些文件，输出写入独立工作目录。演示命令不会删除、重写或移动 `fixtures/` 下的任何文件。

## 六、校验

每个文件的 SHA256 记录在 `demo_manifest.json` 的 `sha256` 字段中，项目根目录的 `SHA256SUMS.txt` 也包含这些文件的校验和。可使用系统自带校验工具核对，例如 Linux 或 macOS 下的 `sha256sum -c SHA256SUMS.txt`，Windows 下可使用 PowerShell 的 `Get-FileHash`。
